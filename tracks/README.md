# tracks/

Imported audio — anything not generated by `tools/synth.py`.

Audio files here are **git-ignored**. They're yours, they may be large, and
they don't belong in the repo. What *is* tracked is the scene definition in
`scenes/scenes.yaml` that refers to them, so the show is reproducible for
anyone who has the same files.

## Importing

```bash
tools/import_track.py ~/Music/thing.wav --id organ_loop
tools/import_track.py <url> --id chant --start 0:12 --take 24
```

The importer converts to the project format (stereo, 44.1 kHz, 96 kbps,
loudness-matched), reports
what the file will cost you in flash, runs onset detection, and prints a ready
scene block to paste into `scenes/scenes.yaml`.

To look before you commit to anything:

```bash
tools/import_track.py some.mp3 --analyze-only
```

## How light follows an imported track

The synths report their own event times, so scenes built from them are locked
to the audio by construction. An outside track can't do that, so onsets are
detected from the audio itself, in three bands:

| marker | band | typically | suggested zone |
|---|---|---|---|
| `onset_low` | < 200 Hz | kick, heartbeat, pedal | door |
| `onset_mid` | 200–2000 Hz | voices, piano, melody | towers |
| `onset_high` | > 2000 Hz | cymbals, bells, sibilance | accents |

These land in `audio/markers.json` under the same names the synths use, so a
`pulse:` stream referencing `onset_low` behaves exactly like one referencing
`heartbeat`. Nothing downstream knows the difference.

If it finds too few or too many events, adjust per scene:

```yaml
sensitivity: 0.7      # lower finds more; default 1.1
```

## Scene options for imported audio

```yaml
- id: my_track
  audio_file: tracks/my_track.mp3
  track_at: 0.0        # seconds into the scene to place it
  track_gain: 1.0      # level before the master limiter
  reverb: 0.0          # imported audio defaults to dry — it's already produced
  sensitivity: 1.1     # onset detection threshold
```

## Where the audio actually lives

On the microSD card, and only there. `make publish` pushes the rendered
scenes to `/sd/scenes` and the imported library to the card root, and the
device streams both off the card through its own web server.

It used to be embedded in flash instead, with the card as an experiment. On
2026-09-01 that flipped for good: two of the scenes became real songs, the
image grew past the 1.75 MB OTA slot, and the all-in-flash build was retired
(PROJECT_NOTES §12.15). One consequence is worth knowing before a show — an
empty card slot no longer falls back to embedded scenes, it plays a
one-second chirp. No card, no show.

## What a track costs you now

Nothing you will notice. The card is 32 GB and playback streams, so length is
not the constraint it used to be: a full song is fine where a 20–30 second
`--take` loop was once the only option. Two of the built-in scenes are whole
songs for exactly that reason.

What still costs something:

- **Decode load.** §12.13 measured 96 kbps mono clean on this chip. Higher is
  untested and the S2 has one core, which the light cues also want.
- **Upload time.** `make publish` pushes over WiFi to a microcontroller.
  `make audio` prints the show's total so you know what you are asking for.
- **The porch, not the file.** A good short loop still reads better than three
  minutes nobody stands there for. `--take` is a taste decision now rather
  than a budget one.

## A note on sources

Use audio you have the rights to. Worth remembering that this castle is a
public-facing display, which is why the built-in scenes are original
compositions rather than anything recognisable (see PROJECT_NOTES §13).

Good sources for this kind of material:

- **freesound.org** — huge library, filter by CC0 for no-strings use
- **archive.org** — public-domain recordings, including a lot of pre-1929 material
- **Free Music Archive** and **ccMixter** — CC-licensed music
- Anything you record or perform yourself
